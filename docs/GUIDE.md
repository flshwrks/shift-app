## 1. 全体構成

このアプリは「同一組織の複数店舗＋本部管理」というモデルで動く。

| ロール | 所属 | できること |
|---|---|---|
| **本部管理者** | どの店舗にも属さない | 全店舗を横断管理。店舗の追加・編集・削除 |
| **店舗管理者** | 必ず1店舗 | 自店のシフト・スタッフ・設定・人件費・アンケート・調整依頼を管理 |
| **スタッフ** | 必ず1店舗（掛け持ち不可） | 自分のシフト申請・全員のシフト確認・調整依頼への応答 |

## 2. ログイン方法（3種類のURL）

| 用途 | URL | 認証 |
|---|---|---|
| 店舗のスタッフ・店舗管理者がログイン | `/s/[店舗ID]/login` | 名前選択 + PIN（4桁） |
| 本部管理者がログイン | `/admin/login` | 名前選択 + PIN（4桁） |
| **ログイン不要**でシフト表だけ閲覧 | `/s/[店舗ID]/public/schedule` | 不要（誰でも見られる） |

- 店舗ごとのログインURLは店頭にQRコードとして掲示する運用を想定している。URLは本部管理者が `/admin/stores` からいつでもコピーできる
- PINを5回連続で間違えると15分間ロックされる
- 旧URL（`/login`, `/staff/*`, `/admin/schedule` 等、多店舗対応前のもの）にアクセスすると自動的に新しいURLへ転送される

### ログイン不要のシフト閲覧について（`/public/schedule`）

店舗ログイン画面の「シフト表を見る（ログイン不要）」から開ける。休憩室のタブレット等に固定して、PIN入力なしでその日の予定を確認する用途を想定している。

- 表形式・タイムライン両方の表示に対応
- シフトをタップすると時間・ステータスの詳細が見られる（コメントは表示しない）
- **提出・編集・確定などの操作は一切できない、完全な読み取り専用**
- **注意**: このURLを知っていれば誰でも閲覧できる（PIN不要）。店舗のスタッフ名とシフト予定が、ログインなしで見える状態になることを踏まえて運用すること

## 3. スタッフ向け機能

### シフト申請（`/s/[店舗ID]/staff/shifts`）

希望シフトを入力して提出する。

1. ナビの「申請」をタップして申請ページを開く
   - 提出期間が設定されている月は、自動的にその月に切り替わります
2. 申請したい日付の行にある「入力」ボタンをタップ
3. シフト種別（A〜G）またはカスタムを選んで「決定」をタップ
   - 「休み / 申請なし」を選ぶとその日の申請を取り消せます
4. 全ての日程を入力したら、画面下部の「X日分をまとめて提出」をタップ
5. 提出完了後、各日のバッジが「申請中」に変わったら管理者へ届いています

**ヒント**
- 「前月コピー」で先月と同じパターンをそのまま引き継げます
- シフト済みの日の「コピー」ボタンで同じシフトを複数日に一括適用できます
- 途中で閉じても入力内容は自動保存されます
- 提出期間外の月はロックされ、入力・コピー・提出のボタンが表示されません（赤いバナーで理由が出ます）
- 確定済み（管理者が承認済み）のシフトは編集できません。変更したい場合は管理者に相談し、調整依頼で対応してもらってください

### シフト確認（`/s/[店舗ID]/staff/schedule`）

確定したシフト表を確認する。

1. ナビの「確認」をタップしてスケジュールページを開く
2. 「◀ ▶」で月を切り替える
3. 「表形式」または「タイムライン」を選んで確認
4. シフトに管理者からのコメントが付いている場合は、時間の下に表示される
   - 長いコメントは途中で省略されます
5. シフトをタップすると開始・終了時刻やコメントの全文を確認できる
6. ページ上部に今月の合計勤務時間が表示される

**ヒント**
- タイムライン形式は誰といっしょに働くか一目でわかります
- 自分の列は強調表示されます
- ログイン不要で閲覧できる「公開シフト表」もあります。休憩室のタブレット掲示などに便利です。店舗IDには推測されないランダムな文字が入っているため、URLを知らない人はたどり着けませんが、URL自体を店外に共有しないでください

### 調整依頼（`/s/[店舗ID]/staff/requests`）

管理者からのシフト依頼を確認・応答する。

1. ナビの「依頼」をタップして依頼ページを開く
   - バッジの数字が未対応の依頼件数を表します
2. 「未対応」タブで届いている依頼の日付・時間帯を確認する
3. 「受ける」をタップすると、その日のシフトが自動的に下書き登録される
   - すでにシフトが入っている日は上書き確認が表示されます
4. 「断る」をタップすると辞退として記録される（掲示板型は他の人に回ります）
5. 対応済みの依頼は「過去の依頼」タブに移動する

**ヒント**
- ログイン時に未対応の依頼があるとポップアップで通知されます
- 掲示板型は早い者勝ちです。他の人が先に受けると自動的に締め切られます
- 承諾した後に管理者が依頼を取り消した場合も、次回ログイン時に通知されます
- 日付が過ぎた依頼は自動的に消えるので、古い依頼が残り続けることはありません

### アンケート回答

管理者からのアンケートに回答する。

1. ログイン後、未回答の実施中アンケートがあれば自動的にポップアップで表示される
2. 選択肢を選ぶ
   - 「その他」の選択肢がある場合は自由記述も入力できます
3. 送信すると回答が記録され、管理者側でリアルタイムに集計される

**ヒント**
- 実施中のアンケートは同時に1件までです。新しいアンケートが公布されると、それまでのものは自動的に終了します

### 要望を送る

お店の管理者やアプリの開発者に意見を届ける。

1. 画面右上のメニュー（≡）をタップし、「要望を送る」を選ぶ
   - このメニューには使い方・更新履歴・ログアウトもまとまっています
2. 送信先を選ぶ
   - 「管理者へ」はお店の管理者に届きます。「開発者へ」はアプリ自体の改善要望として開発者に届きます
3. 「要望」か「不具合」かを選ぶ
4. 内容を入力して送信する（2000文字まで）

**ヒント**
- シフトそのものの相談（この日を代わってほしい等）は、要望ではなく直接お店の管理者に伝えるほうが早く解決します
- 「開発者へ」送った内容には、お店の名前やあなたの名前は含まれません
- 同じメニューの「使い方（詳しい版）」から、役割ごとの手順をまとめた読み物を開けます（別サイト）
- アプリの更新内容は、同じメニューの「更新履歴」からいつでも読めます

## 4. 店舗管理者向け機能

店舗管理者は上記のスタッフ向け機能に加えて、以下の管理画面を使える。

### シフト管理（`/s/[店舗ID]/admin/schedule`）

スタッフのシフトを確認・編集・確定する。

1. 「◀ ▶」で表示月を切り替える
2. スタッフが申請したシフトは「未確定」（黄色）で表示される
3. 「すべて確定」ボタンで全未確定シフトを一括承認
   - 件数バッジ付きのボタンが未確定シフトがある場合のみ表示されます
4. セルをクリックして個別に確認・確定・編集ができる
5. 「+ シフト追加」で手動でシフトを作成できる
6. 「未提出者」ボタンで未提出スタッフを確認し、リマインダーをコピーできる

**ヒント**
- 「表形式」はカレンダー全体を俯瞰、「タイムライン」は時間帯ごとの人数確認に向いています
- 各日付のメモ欄に予定やコメントを記録できます
- ログイン不要のシフト閲覧用URLもあります。休憩室のタブレット固定などに活用できます。店舗IDに推測されないランダムな文字が入っているためURLを知らない人はたどり着けませんが、暗証番号は不要なので、URL自体を店外に共有しないでください

### 調整依頼（`/s/[店舗ID]/admin/requests`）

人手不足の日にスタッフへシフトを依頼する。

1. 「依頼管理」ページの「+ 依頼を出す」をタップしてモーダルを開く
   - タイムラインの赤・黄のコマをタップすると日時が自動入力された状態で開けます
2. 「指名型」か「掲示板型」を選ぶ
   - 指名型はスタッフを個別に選択。掲示板型は全員に公開して先着1名が受け取れます
3. 対象日・時間帯・メッセージを入力して「依頼を送る」をタップ
4. 「募集中」タブで各スタッフの応答状況（承諾・辞退・未対応）をアイコンで確認する
5. スタッフが承諾すると「承諾済み」タブに移動する
6. 「承諾済み」タブの「シフトを確定する」ボタンで下書きシフトを確定する

**ヒント**
- スタッフがログインすると未対応の依頼をポップアップでお知らせします
- 承諾済みの依頼を取り消すと、承諾したスタッフへ通知が届きます
- 依頼から確定したシフトは「シフト管理」ページでも確認・編集できます
- 日付が過ぎた依頼は、この画面を開いたときに自動的に削除されます（依頼から確定したシフトは残ります）

### スタッフ管理（`/s/[店舗ID]/admin/staff`）

スタッフの登録・編集・並び替えを行う。

1. 「+ スタッフを追加」ボタンで新しいスタッフを登録する
   - 名前・PIN（4桁）・権限（スタッフ / 管理者）を設定します
2. PINはスタッフがログイン時に使用する番号。クリックで表示/非表示を切り替えできる
3. 「編集」ボタンで名前・権限・PINを変更できる
4. 「▲ ▼」ボタンでスタッフの表示順を変更できる
   - シフト表の列順に反映されます

**ヒント**
- スタッフに「管理者」権限を付与すると管理画面にアクセスできます
- PINを忘れたスタッフは編集から再設定できます

### 設定（`/s/[店舗ID]/admin/settings`）

シフト提出期間の管理と、各種メニューの入口。

1. 「店舗名」は表示のみ（読み取り専用）
   - 変更は本部管理者が店舗管理画面から行います
2. 「シフト提出期間」で月ごとにスタッフが申請できる期間を設定する
   - 未設定の月はいつでも申請可能。期間外はスタッフが提出できなくなります
3. 開始日・終了日を入力すると「保存」ボタンが出るのでタップする
   - 設定済みの月は「解除」で取り消せます
4. 手前の2ヶ月だけ表示されます。先の月は「先の月も設定する」で開く
5. 画面下の「管理メニュー」から「人件費予測」「アンケート管理」「要望」を開く
   - 毎日は使わない機能をまとめてあります。未対応の要望があると「要望」に件数が出ます

**ヒント**
- 翌月の提出期間を今月中に設定しておくとスタッフが早めに申請できます
- ナビの「設定」にバッジが付いているときは、未対応の要望が届いています

### 人件費予測（`/s/[店舗ID]/admin/labor-cost`）

設定から開く。月間の概算人件費を確認する。

1. ナビの「設定」を開き、「管理メニュー」の「人件費予測」をタップする
2. 確認したい月のタブ（過去2ヶ月〜先4ヶ月）を選ぶ
3. スタッフごとに時給を設定する
   - デフォルトは¥1,268（神奈川県最低賃金 2024年10月時点）。実際の時給に合わせて調整してください
4. 月間実働時間 × 時給で概算人件費が自動計算され、スタッフ別・合計が表示される

**ヒント**
- あくまで概算です。残業・深夜割増・各種手当・社会保険料等は含まれません

### アンケート管理（`/s/[店舗ID]/admin/survey`）

設定から開く。スタッフへのアンケートを作成・集計する。

1. ナビの「設定」を開き、「管理メニュー」の「アンケート管理」をタップする
2. タイトル・説明・選択肢を設定して下書きを作成する
   - 選択肢は2つ以上。「その他（自由記述）」の追加も可能です
3. 「公布する」をタップすると実施中になり、スタッフに表示される
   - 実施中は同時に1件まで。新しく公布すると既存の実施中アンケートは自動的に終了します
4. 回答結果はリアルタイムで集計され、選択肢ごとの得票数・割合がグラフで表示される
   - 「その他」の自由記述も一覧で確認できます

**ヒント**
- スタッフはログイン後、未回答の実施中アンケートがあればポップアップで回答を促されます

### 操作の記録（`/s/[店舗ID]/admin/audit`）

設定から開く。誰がいつ何をしたかを確認する。

1. ナビの「設定」を開き、「管理メニュー」の「操作の記録」をタップする
2. 新しい順に、日時・実行した人・操作の内容が並ぶ
3. 権限の変更・スタッフの削除・暗証番号の再発行は赤い文字で表示される
   - 後から問われやすい操作を目立たせています

**ヒント**
- 記録されるのは、シフトの確定・取消・時刻変更・削除と、スタッフの追加・削除・権限変更・暗証番号の再発行、店舗の追加・削除です
- スタッフ自身がシフトを申請した記録は残りません（本人の操作で、後から争いになりにくいため）
- 記録は後から書き換えたり消したりできません。「勝手に変えられた」という相談があったときに確認するためのものです
- スタッフには表示されません。管理者だけが見られます

### 要望（`/s/[店舗ID]/admin/feedback`）

設定から開く。スタッフから届いた要望・不具合報告を確認する。

1. ナビの「設定」を開き、「管理メニュー」の「要望」をタップする
   - 未対応の要望があると「設定」とアイコンに件数のバッジが出ます
2. 「未対応」タブで届いた内容・送信者・種別（要望/不具合）を確認する
3. 対応が終わったら「対応済みにする」で整理する
   - 間違えたときは「対応済み」タブの「未対応に戻す」で戻せます
4. 不要になったものは「対応済み」タブの「削除」で消せる
   - 削除は元に戻せません。未対応のものは削除できません

**ヒント**
- ここに届くのはスタッフが「管理者へ」宛てに送ったものだけです。「開発者へ」宛てのものは本部管理者が確認します
- 要望には個人的な内容が含まれることがあるため、他のスタッフからは見えないようになっています
- 要望を送れるのはスタッフだけです。管理者は受け取って対応する側なので、送信の導線はありません
- 画面右上のメニュー（≡）の「使い方（詳しい版）」から、管理者向けの手順をまとめた読み物を開けます（別サイト）
- アプリの更新内容は、画面右上のメニュー（≡）の「更新履歴」からいつでも読めます

## 5. 本部管理者向け機能

本部管理者はどの店舗にも属さず、全店舗を横断的に扱える。

### 店舗管理（`/admin/stores`）

店舗の追加・編集・削除、ログインURLの管理。

1. 「+ 店舗を追加」で店舗名・店舗ID（slug）を入力して新しい店舗を作成する
   - 店舗IDは英小文字・数字・ハイフンのみ（例: umeda）
2. 「編集」ボタンで店舗名・店舗IDを変更できる
3. 「削除」ボタンで店舗を削除できる
   - スタッフが1人でも登録されている店舗は削除できません（誤削除防止）
4. 「ログインURLをコピー」でその店舗のログインURL（/s/[店舗ID]/login）をコピーできる
   - 店頭のQRコード作成などに使います
5. 「この店舗を管理」でその店舗の管理画面（シフト管理・スタッフ管理等）へ遷移し、本部管理者としてそのまま操作できる

**ヒント**
- 店舗の管理画面のヘッダーにある「本部管理へ戻る」リンクで、ログアウトせずセッションを保ったまま店舗一覧に戻れます
- 「ログアウト」ボタンはセッションを完全に破棄します（次回は本部ログイン画面でPIN再入力が必要）。単に本部へ戻りたいだけなら「本部管理へ戻る」を使いましょう

### 要望（開発者へ）（`/admin/feedback`）

全店舗から開発者へ届いた要望を確認する。

1. ヘッダー下の「要望」を開く
   - 未対応の要望があるとバッジの数字で件数が表示されます
2. 「未対応」タブで内容・送信者・店舗・アプリバージョンを確認する
3. GitHubに起票されている場合は「Issue #番号」から開ける
4. 対応が終わったら「対応済みにする」で整理する
   - 間違えたときは「対応済み」タブの「未対応に戻す」で戻せます
5. 不要になったものは「対応済み」タブの「削除」で消せる
   - 削除は元に戻せません。未対応のものは削除できません

**ヒント**
- ここに届くのは「開発者へ」宛てだけです。各店舗の管理者宛ての要望は、その店舗の管理画面の「設定 → 要望」にあります
- 要望を送れるのはスタッフだけです。管理者・本部管理者は受け取って対応する側なので、送信の導線はありません

### エラーの記録（`/admin/errors`）

アプリの不具合に気づく。

1. 本部管理のナビにある「エラー」を開く
   - 未対応の件数がバッジで出ます
2. 「未対応」タブに、利用者の画面やサーバーで起きた不具合が新しい順に並ぶ
3. 同じ不具合は1行にまとまり、「◯回」と件数で表示される
4. 「詳細を見る」で技術的な情報を確認できる
   - 開発担当に伝えるときはこの内容を渡してください
5. 対応が終わったら「対応済みにする」を押す
   - 同じ不具合が再発したら、新しい行として立ち上がります

**ヒント**
- 利用者から「画面が真っ白になった」と言われたら、まずここを確認してください
- 「画面」は利用者のブラウザで起きた不具合、「サーバー」はアプリの内部で起きた不具合です

### 実働時間の計算方法（休憩控除）

シフト管理・人件費予測などで表示される「実働時間」は、労働基準法の休憩ルールに沿って以下の通り自動控除している。

- 実働8時間超 → 60分控除
- 実働6時間超8時間以下 → 45分控除
- 実働6時間以下 → 控除なし

例: シフトC（8:00〜17:00、9時間）の実働時間は 9h − 60分 = **8時間**。

### 提出期間のロジック

```
periodSet   = 開始日 または 終了日が設定されている
inPeriod    = (開始日が空 または 今日 ≥ 開始日) かつ (終了日が空 または 今日 ≤ 終了日)
isFarFuture = 期間未設定 かつ 表示月が今日から3ヶ月以上先
isLocked    = isFarFuture または (periodSetかつ !inPeriod)
```

ロック中はシフト申請画面の入力ボタン・コピーボタン・提出フッターが非表示になり、赤いバナーで理由が表示される。

### PINと認証

- PINは4桁の数字。ハッシュ化（bcrypt）してDBに保存され、平文では保持されない
- 5回連続で間違えると15分間ロックアウトされる
- ログインセッションは30日間有効
