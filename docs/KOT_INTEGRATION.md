# KING OF TIME 連携（スケジュールCSVインポート）

> 調査日: 2026-08-23 / 対象: KING OF TIME（クラウド勤怠管理）
>
> 目的: KING OF TIME に毎月手入力している「出勤予定（スケジュール）」を、
> シフト管理アプリで確定したシフトからCSVで一括登録できるようにする。

---

## 1. 結論

**実現可能。** KING OF TIME には標準機能として「スケジュールデータ［CSV］」の一括インポートがあり、
オプション契約・API利用申請・追加費用なしで使える。アプリ側は
**管理画面 → 設定 → KING OF TIME 連携** から月次CSVを出力する（`app/s/[storeSlug]/admin/kot`）。

決め手になったのは次の点。

- **CSVの列構成はKOT側で「入力レイアウト」を自由に作れる。** つまり *KOTをアプリの出力に合わせられる*。
  レイアウトを1回作れば、以降は毎月アップロードするだけ。
- 必須項目は「勤務日」と「従業員コード」の2つだけ。アプリが持っていない情報を要求されない。
- 既にスケジュールがある日にインポートすると「更新」扱いになる。作り直しのたびに消す必要がない。

残る不確定要素は**KOT側の設定値（従業員コード・パターンコード・レイアウトの有無）だけ**で、
これは §4 のヒアリングで埋まる。仕様上の障害はない。

## 2. KING OF TIME 側の仕様（調査結果）

### 2-1. スケジュールデータ［CSV］インポート

| 項目 | 内容 |
|---|---|
| 場所 | 管理画面ホーム → エクスポート／インポート → データ入力（インポート） → スケジュールデータ［CSV］ |
| 事前準備 | 「入力レイアウト作成」で列の並びを定義する（初回のみ） |
| 1ファイルの上限 | 10,000件 |
| 登録可能期間 | 取込日の**3ヶ月前 〜 1年1ヶ月後** |
| 既存データ | スケジュール登録済みの日は**更新**扱い |
| 空欄の扱い | 「登録済みの値を残す」/「削除する」をインポート時に選択 |
| エラーになる日 | 振替休日が指定済みの日 |
| 注意 | パターン側に強制設定があると、そちらが優先される |

### 2-2. 入力レイアウトで選べる項目（抜粋）

| 項目 | 形式 | 必須 |
|---|---|---|
| 勤務日 | `yyyyMMdd` または `yyyy/MM/dd` | ● |
| 従業員コード | 半角英数 3〜10文字 | ● |
| パターンコード | 半角英数 3〜10文字 | |
| 出勤予定 / 退勤予定 | 「対象日HH:mm」（対象日 = 当日 / 前日 / 翌日。当日は省略可、`H`・`m` の1桁可） | |
| 勤務開始刻限 / 勤務終了刻限 | 同上 | |
| 休憩予定時間 | 分単位（整数3桁まで） | |
| 休憩開始予定 / 休憩終了予定 | 同上 | |
| 勤務日種別コード | 平日=1 / 法定休日=2 / 法定外休日=3 | |
| 時間帯区分 / 出勤所属コード | 半角英数 3〜10文字 | |
| 全日休暇 / 半休種別名称（`AM`・`PM` 接頭） | 休暇区分名称 | |
| 備考 | 400文字以内 | |
| 時間単位休暇（区分名称 / 開始 / 終了） | | |
| スケジュール汎用フラグ名称 | 対象=1 / 対象外=0 | |

このアプリが出力するのは **勤務日・従業員コード・パターンコード・出勤予定・退勤予定** の5列のみ。
残りは今回の用途（出勤予定の一括登録）に不要なので出さない。

### 2-3. 実運用上の落とし穴

- **ゼロ埋め不足**: KOT側のコードが `007` なのに `7` で渡すと「該当なし」系のエラーになり、
  桁数の問題だと気づきにくい。→ アプリ側に「従業員コードの桁数」設定を用意した。
- **BOM**: ExcelでUTF-8保存すると先頭に見えない印（BOM）が付き、1列目のタイトルが認識されず失敗する。
  → アプリはBOM無しで出力する。**ダウンロードしたCSVをExcelで開いて保存し直さないこと。**

### 2-4. 参考: Web API 方式（今回は採用せず）

KOT には Web API もあり、スケジュールの登録・更新ができる。

- `PUT https://api.kingtime.jp/v1.0/daily-schedules/{employeeKey}/{date}`（単件）
- `PUT https://api.kingtime.jp/v1.0/daily-schedules`（一括・1リクエスト1,000件まで）
- 主なパラメータ: `clockInSchedule` / `clockOutSchedule` / `startEndBreakSchedule` / `workDayTypeCode` / `note`
- 認証: `Authorization: Bearer {token}`。管理画面の「その他 → オプション → KING OF TIME Web API連携設定」で
  アクセストークンを発行し、**接続元IPアドレスの登録**が必要
- レート制限: 企業単位で直近5分に500リクエスト。**利用禁止時間帯あり（8:30〜10:00 / 17:30〜18:30）**
- 既に打刻や勤怠補助項目がある勤務日はエラー

**採用しなかった理由**: (1) 固定IPが必要でVercel（動的IP）から素直に叩けない、
(2) トークンという長期資格情報を1つ増やすことになる、(3) 月1回の作業を自動化する価値に対して運用負荷が重い。
月次のCSVアップロードは1〜2分で終わる。将来、複数店舗で毎月やるのが負担になった段階で再検討する。

## 3. アプリ側の実装

| 項目 | 内容 |
|---|---|
| 画面 | `/s/[storeSlug]/admin/kot`（設定 → 管理メニュー → KING OF TIME 連携） |
| ロジック | `lib/kot.ts`（Reactに依存しない純関数。CSV組み立てと検証） |
| 設定の保存先 | `app_settings`（`store_id, key` の複合キー）。**DBスキーマの変更なし** |
| 出力 | UTF-8（BOM無し）・CRLF改行・ファイル名 `kot_schedule_YYYY-MM.csv` |
| 確認用 | `npx tsx scripts/kot-smoke.ts` |

`shifts` テーブルに列を足さず `app_settings` に載せているのは、このSupabaseプロジェクトを
在庫管理アプリと共有しており（`CLAUDE.md` 参照）、スキーマ変更のリスクを取る必要がないため。
時給（`wage_<user_id>`）と同じ方式。

### 使用する app_settings キー

| キー | 内容 |
|---|---|
| `kot_code_<user_id>` | そのスタッフのKOT従業員コード |
| `kot_pattern_<shift_type>` | シフト種別（A〜G / custom / off）に対応するパターンコード |
| `kot_date_format` | `slash`（2026/09/01）/ `compact`（20260901） |
| `kot_output_mode` | `both`（既定）/ `pattern` / `time` |
| `kot_code_digits` | 従業員コードのゼロ埋め桁数（0 = 埋めない） |
| `kot_include_off` | 休みの行も出力する（`1` / `0`） |
| `kot_include_draft` | 申請中のシフトも含める（`1` / `0`） |
| `kot_header` | 1行目にタイトル行を付ける（既定 `1`） |

### 出力されないシフト（意図的）

- 従業員コードが未設定、または半角英数3〜10文字でないスタッフ
- パターンコード未設定の「休み」（休みは予定時刻では表現できないため）
- 「パターンコードのみ」設定でパターンコード未設定の種別
- 申請中（`draft`）のシフト（設定で含められる）

いずれも画面上に理由付きの警告として出るので、黙って落ちることはない。

## 4. ヒアリング

### 4-0. 確認済み（2026-08-23 時点）

| 内容 | 状況 |
|---|---|
| KOTに入れているのは**予定だけ**。実績は店頭の出勤ボタン（打刻）で管理 | 再インポートで予定を上書きしても実績は壊れない。ただし**打刻済みの過去日には入れない**方針にする |
| 手入力に時間がかかっているのは**予定の入力そのもの** | CSV化の効果がそのまま出る |
| 休憩を予定として入力していない（ほぼ確実、要最終確認） | 「休憩予定時間」列は不要 → **追加実装なし** |
| 日跨ぎ・深夜勤務は無い | 8:00〜22:00 前提のままでよい → **追加実装なし** |
| **パターン（勤務区分）が全社共通で、他店舗のぶんも大量にある。一覧から選ぶのが面倒** | **CSV化の最大の効果がここ。** 取り込みならコードを直接指定するので選ぶ必要がない。ただし*自店で使っているパターンの特定*が要る |

→ 追加実装が要る懸念は**すべて解消**。残るのは「自店のパターンコードをどう特定するか」だけ。

### 4-1. 質問項目（全体）


**KOTの管理画面を見ながらでないと答えられない項目が多い。**
「管理画面を開いて確認してもらう時間を10分もらう」形で依頼するのが早い。
★ は**これが分からないと出力できない**必須項目。

### A. 権限とアクセス（前提確認）

1. ★ KOTの**管理者アカウント**を持っているのは誰か。CSVインポートの操作をするのはその人か。
2. 管理者権限に「エクスポート／インポート」メニューが含まれているか
   （権限区分によっては非表示。ホーム画面にメニューが出ているかで判断できる）。
3. 今の運用では、誰が・毎月いつごろ・どれくらいの時間をかけて出勤予定を手入力しているか。

### B. 従業員コード（★最重要）

4. ★ KOTに登録されている**全スタッフの「従業員コード」と「氏名」の一覧**がほしい。
   - 取得方法: 管理画面 → 従業員設定（または「従業員データ［CSV］」のエクスポート）
   - シフト管理アプリ側のスタッフ名と**表記が一致しているか**（旧姓・カナ・スペースの有無）も確認する
5. ★ 従業員コードは**ゼロ埋めされているか**（`7` なのか `007` なのか）。桁数は何桁か。
6. 退職者・休職者のコードが残っていないか（残っていると誤登録の元になる）。

### C. パターン（勤務区分）（★重要）

7. ★ KOTに登録されている**パターン（勤務区分）の「パターンコード」と「パターン名」の一覧**がほしい。
   - 取得方法: 管理画面 → 設定 → スケジュール → パターン設定
8. ★ アプリのシフト種別 A〜G は、KOTのどのパターンに対応するか。

   | アプリ | 時間 | KOTのパターンコード |
   |---|---|---|
   | A | 8:00〜13:00 | |
   | B | 9:00〜14:00 | |
   | C | 8:00〜17:00 | |
   | D | 9:00〜18:00 | |
   | E | 13:00〜22:00 | |
   | F | 17:00〜22:00 | |
   | G | 9:00〜22:00 | |
   | カスタム | 都度 | （不要。時刻で渡す） |
   | 休み | — | （公休を登録するなら必要） |

   > 対応するパターンが無い場合、KOT側でパターンを新規作成してもらうか、
   > 「予定時刻のみ」出力に切り替える（アプリの設定で選べる）。
9. 対応するパターンが無い時間帯があれば、**新しくパターンを作ってよいか**（誰の承認が要るか）。
10. パターンに「強制設定」が入っているものはあるか（インポートした予定時刻より優先される）。

### D. 運用ルール

11. ★ KOTに登録したいのは**出勤予定だけ**か、**公休（休みの日）も**登録したいか。
12. ~~休憩時間を予定として登録しているか~~ → **入力していない（確認済み）。列の追加は不要。**
13. ~~深夜・翌日にまたがる勤務はあるか~~ → **無い（確認済み）。**
14. 「所属」を複数持つスタッフ（ヘルプ勤務など）はいるか。あれば「出勤所属コード」列が要る。
15. スケジュールを入れるタイミングは月何日ごろか。締切はいつか。
16. アプリ側のシフト確定 → KOT取り込みの間に、KOT側で直接直すことはあるか
    （あるなら、再インポートで上書きされることを共有しておく必要がある）。

### E. インポート設定の確認（初回の取り込み時に一緒に見る）

17. ★ 「スケジュールデータ［CSV］」の**入力レイアウトが既にあるか**。無ければ新規作成する
    （列の並びはアプリ画面の「KING OF TIME 側の準備」に表示される）。
18. インポート時の「空欄項目の扱い」は「登録されている値をそのまま残す」を選ぶ想定でよいか。
19. 日付形式は `yyyy/MM/dd` と `yyyyMMdd` のどちらが通ったか（初回に実際に試して確定する）。

## 4-B. そのまま送れる依頼文

§4-0 で「予定だけ入力」「休憩なし」「日跨ぎなし」「パターンが大量で選ぶのが面倒」は
**社内で既に分かっている**ので、そこは聞かない。残っているのは次の3つだけ。

| 聞くこと | なぜ要るか |
|---|---|
| ★ エクスポート／インポートのメニューが見えるか | **唯一のブロッカー。** 権限が無ければCSV取り込み自体ができない |
| ★ 従業員コード（氏名との対応・ゼロ埋めの有無） | 出力に必須 |
| ★ 自店で使っているパターンのコード | 大量にあるので**全部ではなく、いつも使う5〜7個だけ**と明示する |

副次的に、公休をKOTに入れているか／複数所属のスタッフがいるかも一言で聞ける。
**1通で足りる。**

> お疲れさまです。
> KING OF TIME の出勤予定の入力、毎月お手数をおかけしています。
> シフト管理アプリで組んだシフトから CSV を出して、一括で取り込めるようにできそうです。
>
> 取り込みだとパターンを一覧から選ぶ必要がなく（コードで直接指定するので）、
> 「他店舗のパターンが大量にあって選ぶのが大変」という部分がまるごと無くなります。
>
> 設定を合わせたいので、管理画面で3つだけ確認していただけますか。
>
> **① エクスポート／インポートのメニュー**
> ホーム →「エクスポート／インポート」を開いて、
> 「スケジュールデータ［CSV］」という項目があるか教えてください。
> **無ければ権限の問題かもしれないので、その旨だけで大丈夫です。**
>
> **② 従業員コード**
> 設定 → 従業員 → 従業員設定 で、氏名と従業員コードの対応を教えてください。
> 人数が多ければ「従業員データ［CSV］」を出力したファイルでも大丈夫です。
> あわせて、コードが「7」の形か「007」のようにゼロで埋まっているかも教えてください。
>
> **③ いつも使っているパターン**
> **全部でなくて大丈夫です。** うちで実際に使っている5〜7個くらいについて、
> パターン名とパターンコードを教えてください（設定 → スケジュール → パターン設定）。
>
> 　※ もし、すでに入力済みの月（先月・今月など）のスケジュールを
> 　　 エクスポートできるようなら、そのファイルをいただければ②③は不要です。
> 　　 実際に使っているぶんだけ入っているので、探していただく手間が省けます。
>
> ついでに2点だけ:
> - 休み（公休）も KING OF TIME に入れていますか
> - 複数の店舗・所属をまたいで勤務するスタッフはいますか
>
> 最初は1人・1日分だけで試して、問題なく入ることを確認してから本番に移します。

### 返事が来たあとの分岐

| 返事 | 対応 |
|---|---|
| ①のメニューが無い | **最大のブロッカー。** 権限区分に「エクスポート／インポート」が含まれていない。本社に権限付与を依頼するか、取り込み作業を権限のある人に任せる |
| ③のコードが分からない／探すのが大変と言われた | 試験取り込みで**「予定時刻のみ」**を試す。通ればパターンの特定作業ごと不要になる |
| 対応するパターンが無い時間帯がある | KOT側で新規作成してもらうか、その種別だけ時刻で渡す |
| 複数所属のスタッフがいる | 「出勤所属コード」列の追加が必要（アプリ側に軽微な追加実装） |
| 公休も入れている | 公休用パターンコードを聞き、アプリの「休みの日も出力する」をONにする |

## 4-C. 管理画面の実物確認（2026-08-24）

KOT管理画面のスクリーンショット3枚で確認した結果。**方針が確定した。**

### ① エクスポート／インポート画面

- **「スケジュールデータ［CSV］」は表示されている** → 想定していた最大のブロッカー（権限）は**クリア**
- インポートに出ているのは「単価データ」「所属／タイムレコーダーデータ」「スケジュールデータ」の3つ
- **「データ出力（エクスポート）」の見出しはあるがボタンが1つも無い** → エクスポート権限が無い。
  「入力済みの月をエクスポートして逆引きする」案は**使えない**

### ② 従業員設定（従業員コード）

| 従業員コード | 名前 |
|---|---|
| 1592 | 川端 礼子 |
| **000** | 佐藤 菜緒子 |
| 1024 | 嵐 紅音 |
| 1577 | 青木 萌音 |
| 1609 | 恩田 惟来 |
| 1637 | 大場 優愛 |
| 1676 | 杉野 千佳子 |

- **桁数が揃っていない**（4桁が主だが `000` だけ3桁）。
  → **ゼロ埋め設定は 0（桁揃えしない）が正解。** 4桁に揃えると `000` が `0000` になり存在しないコードになる
- `000` は3文字ちょうどで、KOTの下限（3文字）を満たすのでそのまま通る
- 画面はスクロール途中。**全員分はまだ取れていない**

### ③ パターン設定 ← ここが決定打

| No. | パターンコード | パターン名 |
|---|---|---|
| 1 | `08001700` | 8-17 |
| 2 | `shibutika` | 9-18 |
| 3 | `zentenyou` | 10-19 |
| 4〜8 | `zentenyou1`〜`zentenyou5` | 9-14 / 9-16 / 9-18 / 9-20 / 9-17 |
| **9〜18** | **（空欄）** | 10:15-16:15 / 10:15-18:15 ×2 / 10:15-18:45 / 10:15-19:15 / 10:15-20:30 / 10-15 / 11-15 / 11-16 / 11:30-20:30 |

分かったことが3つ。

1. **パターンコードが入っているのは最初の8件だけで、9件目以降は空欄。**
   CSVインポートはパターン*コード*で指定するため、**コードが空のパターンはCSVから指定できない。**
   しかも自店で使っていそうな 10:15始まりの時間帯が、まさにコード未設定の側にある。
2. **パターン名が「10:15-18:15」のように時刻そのもの。** 正社員／アルバイトのような勤務区分としての
   意味を持っておらず、**時間帯の別名でしかない。** つまり予定時刻を直接入れれば等価。
3. **アプリのシフト種別 A〜G と KOT のパターンが体系として噛み合っていない**
   （A 8:00-13:00 / E 13:00-22:00 などに対応するものが見当たらない。
   同じ「10:15-18:15」が色違いで2つあるのは、店舗ごとに別々に作られているため）。
   加えてアプリには任意時刻の「カスタム」があり、これはそもそもパターンで表現できない。

### 追加確認（2026-08-24）

- **No.9以降（10:15始まりなど）は基本使わない。1時間単位のパターンしか使わない。**
  → 実際に使うのは **No.1〜8 で、これは全てパターンコードが付いている**
- `000` は**派遣社員**でコード体系が違うため。桁揃えしないのが正しいと確定
- **スタッフは上記7名で全員**（一覧は完結していた）

### 結論: レイアウトは5列で作り、パターンコードは「分かるものだけ」入れる

当初は「予定時刻のみ（4列）」を想定したが、使うパターンにコードが付いていると分かったので
**「パターンコード＋予定時刻」（5列）を1つ作る**のが最善。理由は次のとおり。

- **レイアウトを作り直さずに方針を変えられる。** パターンコードは空欄で構わないので、
  「全部時刻で渡す」も「一部だけパターンを使う」も同じレイアウトのまま切り替えられる
- 対応するパターンが無いシフト種別（A/E/F/G・カスタム）は**空欄のまま時刻だけで登録できる**
- アプリの「カスタム」シフト（任意時刻）もそのまま通る

**作ってもらう入力レイアウト（この順番の5列）**

| # | 項目 |
|---|---|
| 1 | 勤務日 |
| 2 | 従業員コード |
| 3 | パターンコード |
| 4 | 出勤予定 |
| 5 | 退勤予定 |

**アプリ側の設定**

| 設定 | 値 | 理由 |
|---|---|---|
| 出力する内容 | **パターンコード＋予定時刻** | 上記。5列レイアウトと一致させる |
| 従業員コードの桁数 | **0（桁揃えしない）** | `000`（派遣）と `1592` が混在するため |
| 休みの日も出力する | OFF | 公休用パターンが見当たらない |
| 日付の形式 | まず `2026/09/01` | ダメなら `20260901` |

**従業員コード（確定・7名）**

`1592` 川端 礼子 / `000` 佐藤 菜緒子 / `1024` 嵐 紅音 / `1577` 青木 萌音 /
`1609` 恩田 惟来 / `1637` 大場 優愛 / `1676` 杉野 千佳子

**パターンコードの対応（暫定）**

| アプリ | 時間 | KOTパターン | コード |
|---|---|---|---|
| C | 8:00〜17:00 | 8-17 | `08001700` |
| B | 9:00〜14:00 | 9-14 | `zentenyou1` |
| D | 9:00〜18:00 | 9-18 | `shibutika` か `zentenyou3` ★要確認 |
| A / E / F / G | 8-13 / 13-22 / 17-22 / 9-22 | 見えている範囲に無し | 空欄のまま（時刻で登録される） |
| カスタム | 都度 | — | 空欄（仕様どおり） |

> ★ `zentenyou` は「全店用」、`shibutika` は特定店舗用と読める。自店がどちらを使うかは要確認。
> 分からなければ**空欄のままでよい**（時刻で登録されるので実害がない）。

**残る確認事項は「入力レイアウトを作れるか」の1点のみ。**

### 入力用テンプレートが取れるならそれが最短

「スケジュールデータ［CSV］」の画面には「**入力用テンプレートのダウンロード**」がある。
これは**レイアウトを選んでから**、そのレイアウトの列構成でタイトル行だけのCSVを出す機能。

| 状況 | 対応 |
|---|---|
| **既にレイアウトがある** | テンプレートを落として送ってもらう。1行目がそのまま正解の列構成なので、**アプリの出力をそれに合わせる**。レイアウトを新規作成しないので本社確認も不要 |
| **レイアウトが無い** | 先にレイアウト作成が必要。テンプレートはその後 |

既存レイアウトが他店と共用なら**触らずに新規で1つ足す**（レイアウトの追加は既存に影響しない）。

> ⚠️ 既存レイアウトの列がこちらの5列と**順番・項目とも一致しない**場合、
> アプリ側の出力列を可変にする必要がある（現状は `outputMode` に応じた固定の並び）。
> テンプレートを見てから判断すること。先回りして作り込まない。
> 特に**「出勤予定／退勤予定」が入っていないレイアウト**だとパターン方式を強制されるため、
> A/E/F/G のようにパターンが無い種別を登録できなくなる。その場合は列の追加を依頼する。

## 4-D. レイアウト作成ボタンが見当たらない（2026-08-24）

スマホから「スケジュールデータ［CSV］」を開いても、レイアウトも作成ボタンも無かった。
原因の候補は2つ。**①を先に潰す（無料・即時）。**

### ① スマホ表示で右側が切れている ← 可能性が高い

証拠: 送られてきた画面写真は**右端で見切れている**（右上の企業名が「cvyok」「21b 株」で途切れ、
緑のフッター帯も切れている）。ページ幅がビューポートより広い。
KOTの「エクスポート／インポート」画面は、データ種別のボタンの**右側に**
「入力レイアウト作成」が並ぶ作りなので、これが画面外に出ている可能性がある。

→ **PCブラウザで開いて確認してもらう**（または横スクロール）。

### ② 権限で作成できない

「データ出力（エクスポート）」の見出しはあるのに**ボタンが1つも無い**ことから、
この管理者アカウントは権限が絞られているのがほぼ確実。
同様に「レイアウト作成」も許可されていない可能性がある。

→ 本部に「入力レイアウトを1つ作ってほしい」または「レイアウト作成権限がほしい」と依頼する。
**後者の方が長期的に楽**（今後列を変えたくなったとき自分で直せる）。

## 5. 導入手順

1. §4 の B・C でコード一覧をもらう。
2. アプリの **設定 → KING OF TIME 連携** で従業員コード・パターンコードを入力する。
3. 「KING OF TIME 側の準備」を開き、表示される列の順番どおりに KOT で入力レイアウトを作る（初回のみ）。
4. **まず1人・1日だけのデータで試す**（テスト用の月を選び、対象を絞ってダウンロード）。
   取り込めることを確認してから本番の月に進む。
5. 月次運用: シフト確定 → CSVダウンロード → KOTでアップロード → 確認画面で件数を確認 → 登録。

> ダウンロードしたCSVは**Excelで開かない**。中身を見たいときはメモ帳で開く。
