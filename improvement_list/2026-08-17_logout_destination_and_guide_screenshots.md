# ログアウト後の遷移先の修正と、完全版ガイドへの画面写真の組み込み（Ver.2.9.1）

## 1. 本部管理者のログアウト先が店舗のログイン画面になっていた

**症状**: 本部管理者が店舗の管理画面からログアウトすると、本部のログイン画面ではなく
その店舗のログイン画面に飛ばされる。URLを覚えていないと本部に戻れない。

**原因**: リダイレクトの競合。`components/AppMenu.tsx` の `handleLogout` は
ロールを見て `/admin/login` を遷移先に決めていたが、`logout()` で `user` が null になると
店舗レイアウト（`app/s/[storeSlug]/staff/layout.tsx` /
`app/s/[storeSlug]/admin/layout.tsx`）の

```
if (!user) router.replace(`/s/${storeSlug}/login`)
```

が**後から発火して上書き**していた。**ログアウト後はロールが消えているため、
レイアウト側では「この人は本部管理者だった」と判別しようがない。**
Ver.2.1.0 で「ロールを先に見る」修正を入れていたが、それはこの競合までは見ていなかった。

**対応**: `router.replace`（クライアント側のルーティング）ではなく
`window.location.replace`（完全な遷移）にした。クライアント側のルーティングに
割り込まれなくなる。あわせて Cookie を消す `/api/logout` の完了を待ってから遷移するようにした
（遷移が先だとリクエストが中断されうる）。

**別解として検討したが採らなかったもの**:
- レイアウト側の redirect を消す → 未ログインで直接URLを叩かれたときに素通りしてしまう
- ログアウト先を sessionStorage に置いてレイアウトに読ませる → 状態を1つ増やすわりに、
  完全な遷移1行で解決する問題

## 2. 店舗のログイン画面から本部へ戻れるようにした

`app/s/[storeSlug]/login/page.tsx` の左下に「本部管理者の方はこちら」を追加。
1.の修正で通常はここに来なくなるが、URLを直接開いた場合など他の経路もあるため、
戻り道自体を用意しておく。スタッフの導線の邪魔にならないよう、開発者ボタンと同じ控えめな扱いにした。

## 3. 完全版ガイドに画面写真を組み込んだ

運用者が撮影した12枚を、役割ごとのページに配置した。

- 元画像は 1080px 幅。**760px に縮小し、余白や見切れた部分をトリミング**して JPEG(q74) にした。
  12枚の合計 0.45MB（base64で約0.6MB）。ページ全体で 0.67MB に収まっている
- スマホでは入りきらず撮れなかった画面のうち、**自分が実装して中身を把握している2つ
  （要望の送信画面・設定画面の管理メニュー）はHTMLで作り直して**figureに置いた
- **タイムラインとアンケートの集計画面は、実物を見ていないので再現していない**。
  想像で描くと説明が実物と食い違うため、figureごと削除して文章のみにした。
  必要になったら撮影して差し替える

### 撮影用データ

`test` 店舗に撮影用の状態を作ってある（`main` には一切触れていない）。
スタッフ6名（PINは全員 1111）、8/25以降が未確定のシフト、依頼3パターン、
実施中のアンケート、未対応の要望2件など。
作り直す場合のスクリプトは会話ログにあるが、恒久的に必要なものではないため
リポジトリには置いていない。
