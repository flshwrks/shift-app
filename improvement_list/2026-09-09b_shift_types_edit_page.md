# シフト種別を「専用の編集画面」＋「追加・削除・並べ替え」に作り直した

## 対象

- `app/s/[storeSlug]/admin/shift-types/page.tsx`（新規・編集専用ページ）
- `app/s/[storeSlug]/admin/settings/page.tsx`（読み取り専用の一覧＋導線に戻す）
- `lib/shiftPatterns.ts`（データモデルを順序つきリストに変更）
- `components/ShiftPatternEditor.tsx`（削除。専用ページへ移した）
- 参照側4ファイルから `enabledPatterns()` を撤去
- `tests/shiftPatterns.test.ts`（21件 → 34件）

## 変更内容

同日の 2.13.0 で入れた実装を、2点の指摘を受けて作り直した。

**1. 常に編集可能な状態をやめた。**
設定画面には読み取り専用の一覧と「編集する」ボタンだけを置き、編集は
`/s/[店舗ID]/admin/shift-types` へ分離した。年に数回しか触らない設定を
常時編集可能にしておくと、他の設定を見に来ただけで誤って触れてしまう。

**2. チェック式をやめ、追加・削除・並べ替えにした。**
`enabled` フラグで7件を出し入れする方式から、**使う種別だけを順序つきで持つ配列**に変更。

- 追加：空いている記号のうち、いちばん若いものを自動で割り当てる（最大7件）
- 削除：確認を挟んでから外す。最後の1件は消せない
- 並べ替え：↑↓で入れ替え。**並び順がシフト入力画面の表示順になる**

## 設計判断

**記号(A〜G)は並べ替えでも振り直さない。**
`shifts.shift_type` に保存されているのがこの記号なので、並べ替えのたびに振り直すと
**過去のシフトが別の種別を指してしまう**。並び順は配列の順序で持ち、記号は識別子として固定した。
そのぶん「C, A, B」のような並びになりうるが、データの正しさを優先する。
画面にも「記号は並べ替えても変わりません」と明記した。

**削除した記号は `findPattern` で null を返す。**
過去のシフトがその記号を使っている場合、呼び出し側はシフト行の
`start_time` / `end_time` を出す（定義ではなく実績を出す）。既にそうなっていることを確認済み。

**旧形式（`enabled` 付きの7件）も読める。**
`parsePatterns` は `enabled: false` の項目を取り除いて読む。2.13.0 を保存した店舗があっても壊れない。

**1件も残らない指定は既定値に戻す。**
空配列や不正な記号だけのJSONが来た場合、画面が空になると入力そのものができなくなるため。
