# 他アカウントでログイン中に店舗ログイン画面を開いたときの挙動

## 対象

- `app/s/[storeSlug]/login/page.tsx`

## 症状

本部管理者としてログインしているタブがある状態で、別タブから店舗のログイン画面
（`/s/<slug>/login`）を開くと、**何の説明もなく本部の画面（`/admin/stores`）へ飛ばされる**。
利用者からは「勝手に本部管理者に切り替わった」ように見える。

## 原因

ログイン画面に「ログイン済みならホームへ送る」処理があり、
**自店・他店・本部を区別していなかった**。

```ts
useEffect(() => {
  if (!user) return;
  router.replace(homePathFor(user.role, storeSlug));   // 本部なら /admin/stores
}, [user, router, storeSlug]);
```

本部管理者は店舗に属さないため `homePathFor()` は常に本部のホームを返す。
結果、店舗のログイン画面を開くたびに本部へ引き戻されていた。他店のスタッフでも同じことが起きる。

## 変更内容と、その判断理由

**素通しは「自店のログイン画面に、その店舗の人が来た場合」だけに限定した。**
QRコードやブックマークから再訪したスタッフに毎回ログイン画面を見せるのは煩わしいので、
この経路は従来どおり残す必要がある。

**それ以外（本部・他店）は黙って飛ばさず、状態を見せて選ばせる。**
「現在 ◯◯（本部管理者）としてログインしています」と出し、
「そのまま続ける」「ログアウトしてこの店舗でログインする」の2択にした。

ログアウト処理は `components/AppMenu.tsx` と同じ形にしている
（`/api/logout` でCookieを消し切ってから `window.location.replace`）。
`router.replace` だと、ログアウトで `user` が null になった直後に
店舗レイアウトの「未ログインならログイン画面へ」が発火して行き先を上書きしうる。

## この修正で解決しないこと

**1つのブラウザで2つのアカウントに同時ログインすることはできない。**
セッションはCookieで持っており、Cookieはタブではなくブラウザ（プロファイル）単位で共有される。
本部と店舗を並べて確認したい場合は、シークレットウィンドウか別のブラウザを使う。
画面にもその案内を出している。

## 検証

ローカルの開発サーバーで、開発者ログイン（本部相当）した状態から `/s/main/login` を開き、

- 本部のホームへ飛ばされず、新しい選択画面が出ること
- 「ログアウトして…でログインする」でCookieが消え、通常のログイン画面に戻ること

を確認した。`npm test`（44件）・`npx tsc --noEmit` も通過。
